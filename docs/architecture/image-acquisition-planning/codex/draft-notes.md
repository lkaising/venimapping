## Data-plane draft notes

### Register disagreements

- `d9` keeps DDS history depth 2. [A] I still prefer depth 1 until a loaded probe shows a delivery benefit from depth 2 within the frame age budget. Depth 2 can retain an older unread frame. [F] CycloneDDS history overwrite has no loss event. The c1 and c3 rate checks give no comparison by reader depth. (`ros:eclipse-cyclonedds/cyclonedds/src/core/ddsc/src/dds_rhc_default.c:854-875`, `docs/architecture/image-acquisition-planning/claude/camera/c1.md:111-119`, `docs/architecture/image-acquisition-planning/codex/camera/c3.md:45-50`)
- `d10`, `d13`, `d24`, and `d28` combine the first-frame rule with a capacity-1 drop-oldest queue. If two frames arrive before the pull, the second evicts the first. [F] In c1, the Mono8 first frame arrived about 79 ms before the start reply. The observed frame period was about 14 ms. [Q] Must get image keep the first push even when the caller cannot take it before the second? [A] I prefer a one-shot latch for get image if the first push is contractual. Otherwise, specify the oldest frame still queued at the pull. The draft follows the registered queue rule. (`docs/architecture/image-acquisition-planning/claude/camera/c1.md:111-119,145-163`, `docs/architecture/image-acquisition-planning/codex/positions.md:79-86,204-210`)
- `d24` and `ic8` describe ordering after `subscribe` returns and imply that the frame sequence exceeds all sequences at the request. `ic3` assigns the sequence before acquiring the fan-out lock. A callback can already have a sequence when the worker links the new queue. It can push before `subscribe` returns. [A] Specify the queue link as the point that orders registration against fan-out. A test can pause a callback before it takes the lock and open the queue during that pause. (`docs/architecture/image-acquisition-planning/register.md:506-516,747-755,860-869`)
- `ic1` makes `ImageFrame` immutable after `create`. `ic3` calls `create` before the lock and then sets epoch fields under the lock. `ic8` also bars allocation under that lock. [A] Allow private staging of a validated frame block. Set the epoch fields under the lock before publishing the immutable frame. Keep the public factory's result immutable. (`docs/architecture/image-acquisition-planning/register.md:629-647,747-755,860-869`)
- `ic1` gives every accessor the type of its field and marks it `noexcept`. Copying a `std::string` field by value can allocate. [A] Use the field's value type for scalars. Return strings by const reference to the shared block, as v1 does. (`docs/architecture/image-acquisition-planning/register.md:615-647`, `docs/architecture/image-acquisition-design-v1.md:686-699`)
- `d26` returns the cold get image result before stop completes. [A] I prefer a cold success to include the stop result. [F] The gateway uses one timeout per call, and a timeout removes the pending request without cancelling its driver work. `d19` reconciliation must finish before a later request can start another stream. Keep the registered caller deadline and asynchronous stop in the draft. (`src/venimapping_camera/include/venimapping_camera/vimbax_camera_gateway.hpp:45-61`, `src/venimapping_camera/src/gateway_support/vimbax_service_calls.hpp:79-94`, `docs/architecture/image-acquisition-planning/codex/positions.md:222-229`)
- `d18` requires a `TriggerSelector` write before every `TriggerMode` readback and bars feature writes during a stream. `d22` can keep a driver-restarted stream after reconnect. [F] The driver can restart after reopen before the worker polls it. The camera permits selector writes while streaming. [Q] Does recovery allow that selector write, or must the worker stop the driver stream before readback? Keep admission closed until the controller verifies the profile. (`driver:vimbax_camera/src/vimbax_camera_node.cpp:556-568,579-593`, `docs/architecture/image-acquisition-planning/claude/camera/c2.md:122-130`)

`d3`, `d6`, and `d14` settle earlier naming and metadata differences. Use `tf_frame` for the coordinate frame, `significant_bits` from the verified profile, and the fixed `ic5` codes. The `d19` and `d22` readbacks supply the trusted bit depth that the earlier position required. (`docs/architecture/image-acquisition-planning/codex/positions.md:21-27,45-51,113-119`)

### Interfaces to match

| Section | Contract |
|---|---|
| Control plane | The worker alone calls `subscribe`, `open_admission`, and `close_admission`. Poll `matched_publishers()` every 10 ms within the 1000 ms limit and the caller deadline (`d17`, `ic2`, `ic8`). |
| Control plane | The worker passes `significant_bits` from `PixelFormat` readback to `open_admission`. The result is `EpochStart{epoch, boundary_ns}`. `receive_seq` stays source-wide and no stamp event creates an epoch (`d11`, `d14`, `d20`, `ic3`). |
| Control plane | At recovery or a cold start, time silence from the relevant start until `last_admitted` advances for that epoch. Check every 100 ms against `max(250 ms, 5 × period)` (`d22`, `ic3`, `ic8`). |
| Control plane | A `Feed` owns one subscription and one lease. Its pulls and stats forward to the subscription. Close clears and wakes the subscription, then posts lease release (`d17`, `ic2`). |
| Control plane | Get image uses its own capacity-1 subscription and waits on the caller thread. The worker owns stream calls and lease changes. The controller rejects an additional request of the same kind with `kRequestBusy` (`d13`, `d26`, `d28`, `ic4`). |
| Error vocabulary | Use `ErrorDomain::kAcquisition = 2` and `Error::from_acquisition`. The data plane returns only `kFeedClosed = 1`, `kWrongThread = 7`, `kInvalidArgument = 10`, and `kSourceCreateFailed = 11` (`d6`, `ic5`). |
| Error vocabulary | An empty pull succeeds. Suspended admission leaves pulls open. The callback reports layout, stamp basis, and admission discards in counters (`d12`, `d22`, `ic3`, `ic5`). |
| Bring-up | Pass the same `camera_namespace` to both adapters. Pin `autostream: 0`, `buffer_count: 7`, and `image_raw.enable_pub_plugins: ["image_transport/raw"]`. Freeze the time parameters during acquisition (`d8`, `d10`, `d20`, `ic6`). |
| Bring-up | Set `use_ros_time: true` on the driver and `use_sim_time: false` on the driver and application node. Check the parameter before start and the first header against receipt realtime (`d20`, `ic6`). |
| Testing | `FakeFrameSource` uses `FrameFanout` with injected `realtime_ns()` and `steady_now()`. It forwards `inject(...)` to `on_message` and exposes `set_matched_publishers(n)` (`ic7`). |
| Testing | Use a RELIABLE, KEEP_LAST 10 publisher on a test namespace for the adapter test. Check conversion, matching, sequence, and the 1 s stamp basis discard (`ic7`). |
| Testing | Record match time, callback duration, and gateway round-trip time at rest and at 69.7 Hz Mono8. Run the device stamp probe separately at 30 Hz and 69.7 Hz (`d5`, `d12`, `d20`, `ic7`). |
| Testing | The separate probe disables `use_ros_time` and uses its own raw reader with `rclcpp::MessageInfo`. It records device stamp and DDS source timestamp deltas without the controller (`d20`). |
| Implementation sequence | Land the acquisition error types before the frame API library. Add the ROS-free tests with the frame API. Add `sensor_msgs` and the ROS adapter test only at the adapter step (`ic8`). |
| Implementation sequence | Compile `src/image_frame.cpp` and `src/frame_support/frame_fanout.cpp` into `venimapping_camera_frame_api`. The controller and fake can build before `venimapping_camera_vimbax_frame_source` (`ic0`, `ic7`, `ic8`). |
