## Interface mismatches

1. [F] The data plane requires `open_admission(significant_bits)` before each project start. The reconnect path omits the argument when it keeps the driver restart. It omits the call when it starts again. See r-codex-1. (`codex/sections/data-plane.md:78-86,98-102`, `claude/sections/control-plane.md:270-277`)
2. [F] The controller uses `frames_received` as the last assigned sequence. The data-plane section gives the increment order without stating that both values use one atomic increment starting at 1. The queue link and sequence cutoff need separate rules. See r-codex-3. (`codex/sections/data-plane.md:104-113`, `claude/sections/control-plane.md:194-210`, `claude/draft-notes.md:78`)
3. [F] The register gives `Feed` a unique subscription. The control-plane draft shares it with the worker for shutdown. Agree on a close path that can outlive the controller and the source. See r-codex-17. (`register.md:703-711,739-743`, `codex/sections/data-plane.md:68-94`, `claude/sections/control-plane.md:96,293-303`)
4. [F] The draft fake names `FrameFanoutClock`. The data-plane section leaves the type and lifetime open. The in-flight test needs to control that clock while a callback waits before fan-out. The probe also needs a duration value that `FrameSourceStats` does not expose. See r-codex-13. (`claude/draft-notes.md:84-85`, `claude/sections/testing.md:39-50,112,152-153`, `codex/sections/data-plane.md:56-66,104-111`)
5. [F] The error table's reader rejection description is narrower than the adapter's RMW event contract. The control-plane uses of `kFeedClosed` and `kInvalidArgument` also need the IC5 update proposed in the draft notes. The data-plane code set remains 1, 7, 10, and 11. See r-codex-14. (`claude/sections/error-vocabulary.md:77-94,115-119`, `claude/draft-notes.md:24-29`, `codex/draft-notes.md:24-25`, `register.md:791-808`)
