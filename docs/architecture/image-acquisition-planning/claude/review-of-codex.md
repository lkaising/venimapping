# Review of the Codex sections

This review covers `codex/sections/data-plane.md`, `codex/source-tree.md`, and `codex/draft-notes.md` at checkpoint `f0eb978`. It checks them against `register.md`, the project code, the driver source, and the Claude sections.

Path conventions:

1. A path that starts with `codex/`, `claude/`, or `register.md` is under `docs/architecture/image-acquisition-planning/` in the worktree.
2. Other `path:line` citations are from the worktree root. `driver:` and `ros:` citations use the roots that the register gives.
3. Register ids are in lower case, for example `ic3`.

## Result

No finding is Blocking. The data-plane section follows each register entry and each interface contract, with the deviations that `codex/draft-notes.md` declares. Three findings are Major. Each one is a gap at an interface that a Claude section or test depends on.

`[F]` These Codex citations were checked and support their claims:

1. The publisher uses `rmw_qos_profile_default` with depth 10, which is RELIABLE, KEEP_LAST, VOLATILE (`driver:vimbax_camera/src/vimbax_camera_node.cpp:354-357`, `ros:ros2/rmw/rmw/include/rmw/qos_profiles.h:51-62`).
2. The driver stamps the header after `transform()` and before `publish` (`driver:vimbax_camera/src/vimbax_camera.cpp:1745-1757`, `driver:vimbax_camera/src/vimbax_camera_node.cpp:1605-1631`).
3. Cyclone DDS allows a loan only for a self-contained type (`ros:ros2/rmw_cyclonedds/rmw_cyclonedds_cpp/src/rmw_node.cpp:2949`, `:2984`). `Image` has unbounded `encoding` and `data` (`ros:ros2/common_interfaces/sensor_msgs/msg/Image.msg:21-26`).
4. A user `message_lost` callback that the RMW does not support throws from the subscription constructor, because rclcpp does not catch it (`ros:ros2/rclcpp/rclcpp/src/rclcpp/subscription_base.cpp:162-166`). The Codex rule to create the reader again without the event is therefore necessary.
5. `get_publisher_count()` throws on an rcl failure (`ros:ros2/rclcpp/rclcpp/src/rclcpp/subscription_base.cpp:277-288`). The Codex rule to return 0 needs a catch, and the section states that rule.
6. A full reader history replaces its oldest sample with no lost status (`ros:eclipse-cyclonedds/cyclonedds/src/core/ddsc/src/dds_rhc_default.c:854-875`).
7. The plugin filter parameter is `image_raw.enable_pub_plugins`, and only the listed plugins advertise (`ros:ros-perception/image_common/image_transport/src/publisher.cpp:114-153`).
8. The byte numbers are correct. 4 x 1337472 is 5349888, and 5 x 1337472 is 6687360 (`claude/camera/c1.md:104`).

## Interface mismatches between the Claude and Codex sections

1. `receive_seq` start and relation to `frames_received`. The Claude control-plane section and tests need the first value 1 and `frames_received` equal to the last sequence (`claude/sections/control-plane.md:201`, `:209`, `claude/sections/testing.md:82`, `:140`). The data-plane section gives neither (`codex/sections/data-plane.md:106`). See r-claude-1.
2. Freshness ordering point for get image. The Claude control-plane section uses the queue link and the `receive_seq > R` filter (`claude/sections/control-plane.md:194`, `:209`). The Codex draft notes propose the queue link alone (`codex/draft-notes.md:7`). See r-claude-4. The coordinator also has the d24 text that `claude/draft-notes.md` N1 proposes.
3. Callback duration. The Claude `feed` and `load` probe modes record it (`claude/sections/testing.md:152-153`). `FrameSourceStats` has no field for it (`codex/sections/data-plane.md:56-66`). See r-claude-2.
4. `FrameFanout` clock type and method set. `FakeFrameSource` takes `FrameFanoutClock&` and forwards to `subscribe`, `open_admission`, `close_admission`, `stats`, and `on_message` (`claude/sections/testing.md:44`, `claude/draft-notes.md:84`, M7). The Codex source tree names no clock type and no method set (`codex/source-tree.md:10`). The data-plane owner names both in `frame_fanout.hpp`. The clock is a reference that must outlive the `FrameFanout`.
5. Subscription lifetime. The Claude tests `Fanout.SourceGone` and `Controller.FeedOutlivesController` need a subscription that works after the source is gone (`claude/sections/testing.md:93`, `:128`). The data-plane section gives no ownership model. See r-claude-3.
6. Ownership of the feed subscription. ic2 item 1 and the Codex interface table give `Feed` sole ownership of a `std::unique_ptr<FrameSubscription>` (`register.md:741`, `codex/draft-notes.md:22`). The Claude control-plane section shares the subscription between the worker and the `Feed` (`claude/sections/control-plane.md:303`). The `FrameSource` interface does not change, because a `unique_ptr` converts to a `shared_ptr`. The Claude section must state the conversion, or change to sole ownership with a worker-side close through the `Feed`.
7. `open_admission` before each start call. The data-plane section and d11 item 3 call `open_admission` before each controller start call (`codex/sections/data-plane.md:102`, `register.md:244`). The Claude reconnect step 5 calls `stream_start()` with no new `open_admission` (`claude/sections/control-plane.md:276`). The Claude section must call `open_admission` before that start, so the restart gets its own epoch and boundary.
8. `TriggerSelector` write during a stream. The Codex draft notes leave it as an open question (`codex/draft-notes.md:11`). The Claude control-plane section allows this one write during a stream (`claude/sections/control-plane.md:169`, `:183`). `[F]` The camera accepted selector writes while it streamed (`claude/camera/c2.md:130`). The coordinator can close the question with the d18 item 7 text in `claude/draft-notes.md` N2.
9. Text of `kInvalidArgument` from `subscribe`. `feed_open` passes it through unchanged and needs a text that names the bad capacity (`claude/draft-notes.md:88`, M11). The data-plane section gives no text rule (`codex/sections/data-plane.md:90`).
10. Error layers. The Claude error-vocabulary section adds control-plane rows for `kFeedClosed` and `kInvalidArgument` (`claude/sections/error-vocabulary.md:80`, `:90`). The Codex table lists the data-plane codes only (`codex/draft-notes.md:24`). These are compatible, and the data plane needs no change. ic5 needs the two extra rows.
